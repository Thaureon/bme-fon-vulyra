# Project Retrospective

## Project Window
📅 January 1, 2026 → January 31, 2026

## Original Intent
The original intent of this project was to design and build a tournament website using **Blazor**, capable of supporting multiple tournament formats through a flexible backend and data model.

## Timeline Summary
The project progressed through initial setup and research, followed by early implementation and structural work. As complexity increased and multiple BME-FON projects were worked on in parallel, cognitive load grew and focus became constrained.

Weekly progress logs captured both technical advances and emerging friction, culminating in the decision to conclude the project early to preserve overall sustainability.

## Key Learnings
- Daily and weekly logs help maintain momentum and motivation during projects.
- Figuring out how a piece works is nice, but sometimes black boxes are necessary to complete a project.
- Creating basic database designs and expanding as needed would be better for smaller projects instead of trying to design the entire database from the start.
- Running too many BME-FON projects concurrently reduces depth and accelerates burnout.

## What I'd Change Next Time
- Limit the number of parallel BME-FON projects per month.
    - 2 seems like a good number depending on the complexity of each of them.
- Start with smaller database structure and expand as the project goes on.
    - Avoid making the database "perfect" from the start.
- Define a clearer project scope at the start
    - Create tournament website using Blazor vs learning Blazor to create a tournament website.
- Treat emerging strain as a signal to adjust scope sooner rather than later.
