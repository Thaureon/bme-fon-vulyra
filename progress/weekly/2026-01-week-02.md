# Week 2 - January 2026
📅 January 4 - January 10, 2026

## Summary
The second week marked a transition from high-level research into initial
implementation work using Blazor.

Early in the week, time was spent researching server-side rendering (SSR)
versus client-side rendering (CSR), communication patterns between server and
user, and evaluating Blazor as a foundation for the project. This research
informed the decision to proceed with Blazor and server-side approaches.

Midweek, an initial Blazor project was created and configured, including
authentication scaffolding and local database setup. The latter part of the
week focused on understanding the login flow, token handling, and beginning
to design a database structure capable of supporting multiple tournament
formats.

## What Worked
- Researching SSR vs CSR before committing to an implementation approach
- Using Blazor's built-in project templates to bootstrap authentication and
  page structure
- Incrementally exploring the login flow and security setup instead of treating
  it as a black box
- Beginning database design only after understanding application flow and
  requirements

## What Didn't
- Security and authentication complexity slowed initial momentum
- Tooling friction (Entity Framework version mismatch) introduced setup delays
- Database design raised additional questions around seeding and race-style
  tournaments that were not yet resolved

## Next Week
- Begin implementing database models based on the initial schema
- Validate whether the current database structure can support seeding and
  race-based tournament formats
- Continue refining understanding of Blazor authentication and data flow
